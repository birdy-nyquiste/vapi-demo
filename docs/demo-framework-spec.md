# Vapi Demo 框架实现规格

状态：依据已确认方向整理，供实现使用。2026-09-16。

## 目标

搭建面向开发者的语音 Agent 实验框架：使用真实美国电话体验 inbound 与 outbound，并观察上下文、工具调用和执行结果。Nyquiste 全家桶仅作为首个可替换示例，业务话术和规则不阻塞框架交付。

## 已确定的技术选择

- React + Vite + TypeScript 前端。
- Node.js + Express + TypeScript 后端，通过 Vercel Functions 运行；前后端在一个仓库、一个 Vercel 项目中部署。
- 托管 Postgres 保存运行、事件及工具产生的演示记录；具体供应商尚未选定。
- Telnyx 美国语音号码导入 Vapi，绑定来电助手，并启用美国外呼权限。
- Vapi 负责通话、语音管线和模型工具调用；应用后端不转发音频。
- 页面在有活动通话时约每 2 秒增量轮询事件。

官方能力依据见 [调研笔记](./vapi-capabilities-research.md)。供应商、语音模型与接口兼容性在实际接入时核验。

## 框架与场景的边界

框架拥有：Vapi 接入、通话关联、事件标准化、工具分发、数据持久化、演示界面。

场景拥有：说明、系统提示词、来电和外呼开场白、允许的上下文、工具 JSON Schema、工具处理函数、固定演示资料。

场景通过 TypeScript 模块注册，工具处理函数由代码实现。替换或增加场景需要更新代码并部署；第一版不制作场景编辑器、插件加载器或任意代码执行机制。

建议的模块边界：

```text
src/client/                  页面与事件展示
src/server/vapi/             Vapi API、webhook 解析与鉴权
src/server/runtime/          运行关联、场景注册、工具分发
src/server/storage/          Postgres 查询
src/scenarios/               场景说明、提示词、工具与演示数据
src/shared/                  页面与后端共享的数据类型
```

工具代码、私钥和数据库连接只进入服务端包。前端仅接收可展示的场景说明与运行数据。

## 最小场景契约

每个场景提供：

- `id`、`version`、`name`、`description`。
- `systemPrompt` 与 `inbound` / `outbound` 的开场白及上下文构造函数。
- `tools`：名称、说明、参数 JSON Schema、服务端处理函数。
- 工具处理函数接收服务端解析出的 `runId`、`callId`、`toolCallId`，以及经过运行时校验的参数；返回可序列化结果。

框架把以上配置转换成 Vapi Assistant 配置。一个场景默认使用一个助手，同时覆盖来电和外呼，不要求每个业务阶段拆分助手。

Vapi Assistant 与场景版本的对应关系保存在配置中。每次运行固定记录 `scenarioId` / `scenarioVersion`，修改当前场景不改变历史记录的归属。第一版场景更新在无活动通话时进行。

## 两条通话路径

### Inbound

1. Telnyx 号码绑定一个 Vapi Assistant，该助手对应当前来电场景。
2. 用户拨入，Vapi 应答并向后端发送事件。
3. 后端根据可信的 Vapi call/assistant 信息关联或创建运行记录；以 `callId` 保持唯一性。
4. 工具调用交给该运行对应的场景处理，结果返回 Vapi，并保存到事件列表。
5. 页面发现新来电并显示状态、字幕、工具结果。

来电场景第一版通过配置脚本或 Vapi Dashboard 切换；页面显示当前号码和场景，不提供通话中切换。

### Outbound

1. 页面选择已注册场景和固定演示上下文，点击拨打配置好的测试手机。
2. 后端创建运行记录，调用 Vapi Calls API，传入号码、助手和场景上下文。
3. 保存返回的 `callId`；之后按与来电相同的路径处理事件和工具。
4. 创建通话请求出现不确定结果时保留状态并核对 Vapi，不自动重复拨号。

发起请求成功只表示创建了通话，不表示接听，更不表示业务任务完成。

## 后端接口

以下路径是本应用接口，不是 Vapi 官方接口：

| 接口 | 作用 |
| --- | --- |
| `GET /api/scenarios` | 返回场景说明、演示上下文选项和当前来电配置 |
| `POST /api/calls` | 向服务端配置的测试号码发起外呼 |
| `POST /api/vapi/webhook` | 接收通话事件及同步 Function Tools 请求 |
| `GET /api/runs` | 最近运行列表 |
| `GET /api/runs/:id` | 运行状态与最终记录 |
| `GET /api/runs/:id/events?after=...` | 按持久化游标增量查询事件 |

业务工具统一使用同步服务端 Function Tools；响应按 Vapi 协议使用 `toolCallId` 关联结果。仅执行已注册工具，不根据传入名称动态加载代码。

最小访问保护：演示页面与管理 API 使用简单的服务端访问凭据；外呼目标由服务端允许列表限制。Webhook 使用 Vapi 支持的服务端认证方式单独验证，不能被演示页面登录或 Vercel Deployment Protection 拦住。

## 数据与事件

使用三张小表即可，不建客户、CRM 或订单领域模型：

- `runs`：运行 ID、Vapi call ID（唯一）、场景与版本、方向、状态、上下文快照、开始/结束时间、结束原因。
- `events`：递增游标、运行 ID、事件种类、接收时间、原事件时间（若有）、JSON payload。
- `tool_executions`：运行 ID、tool call ID、工具名、参数、执行状态、结果与错误、耗时；运行 ID 与 tool call ID 组合唯一。

工具返回的 JSON 结果即可承载购买意向、配置状态等演示记录。首版无需再建专用业务表。

处理重复 webhook 时复用已完成工具结果；写入类演示工具在数据库事务内保存结果。事件可能重复或乱序，终态不能被迟到的通话中状态覆盖。字幕区按角色展示，工具输出按 JSON 展示，不为全家桶做专属组件。

观察面板展示实际收到的事件、参数、结果与本后端测得的工具耗时。它不展示模型内部推理，也不把本后端执行耗时标成端到端语音延迟。

## 最小页面

一个页面包含：

1. 入口区：来电号码、当前来电场景；外呼场景、演示上下文、拨号按钮。
2. 最近通话列表：方向、场景、时间和状态。
3. 选中通话详情：字幕、事件时间线、可展开的工具输入输出、结束原因。

拨号按钮在请求处理中禁用；没有凭据或号码时明确显示未配置。页面不默认提供任意电话号码输入。

## 第一套示例

先使用 `echo_demo`：一个 `save_demo_note` 工具保存用户说的一句话并返回记录编号，验证完整执行路径。

随后接入 `nyquiste_bundle`：

- 来电咨询报价与购买意向。
- 外呼配置回访。
- `get_bundle_quote`、`save_purchase_interest`、`save_setup_status` 三个示例工具。
- 产品资料和价格表保存在场景目录，注明来自 https://router.nyquiste.com/plan-config 的页面快照。
- 报价币种、计费周期等页面未明确的信息不自行推断，待业务资料确认；不影响框架开发。
- 不做真实支付或自动安排下一次回访。

## 开发顺序与验收

### 1. 骨架与事件闭环

完成前后端、数据库、场景注册、webhook、运行列表与事件面板。使用明确标为模拟的事件验证页面和接口；模拟结果不能作为真实电话验收。

### 2. 真实电话与单工具

配置 Vapi 和 Telnyx，在美国测试手机上分别验证一次拨入和拨出。使用 `echo_demo` 完成工具调用、保存、返回和页面展示。

### 3. 场景替换与示例

挂载全家桶场景并更新助手配置；通话、webhook、存储和展示组件无需改写。验证报价修正与配置状态保存。

验收要求：

- 两个方向均有真实接通记录。
- 工具参数、实际结果和错误在页面可见；刷新后仍可查看。
- 同一 tool call 重复投递不会新增重复演示记录。
- 工具报错不会被框架包装成成功。
- 从 echo 场景切换到全家桶场景不修改通用运行框架。
- 前后端可在 Vercel 部署，Vapi 能访问公开 HTTPS webhook。

测试聚焦工具分发、参数校验、重复调用和状态乱序；电话与语音体验通过受控真实测试验证。

## 开发时需要的外部配置

- Vapi 私钥、Assistant 配置及 webhook 认证凭据。
- 已导入 Vapi 的 Telnyx 美国号码及其 `phoneNumberId`。
- 美国测试手机号码。
- 托管 Postgres 连接信息。
- Vercel 项目与最终 webhook 地址。

这些配置不阻塞本地框架开发，但缺失时不能完成真实电话或部署验收。

## 首版范围之外

场景可视化编辑器、Squads、知识库平台、模型 A/B 控制台、自动外呼活动、真实交易和 CRM 均留待后续按实验需要加入。
